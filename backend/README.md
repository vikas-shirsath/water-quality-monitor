# FastAPI backend

Create a virtual environment, install `requirements.txt`, copy `.env.example` to `.env`, and set `DATABASE_URL` to the Supabase PostgreSQL connection URI (use the Session pooler on IPv4-only networks). The backend requires PostgreSQL and uses psycopg 3 with SSL. Run `uvicorn app.main:app --reload`. Tables are created on startup for prototype use. `python seed.py` creates three days of sample measurements. Keep database credentials server-side. For production, apply managed schema migrations before startup.

The API accepts sensor data at `POST /api/readings`, serves REST resources under `/api`, and broadcasts `reading.created` and `alert.created` JSON messages over `/ws`. Readings must include `device_id`, `ph`, `tds`, `turbidity`, and `temperature`; timestamps are UTC ISO-8601. Use `GET /docs` for the interactive API schema.

## Experimental dataset model

The dashboard's `model_assessment` is an experimental predicted-category score (`Good`, `Moderate`, or `Poor`) for `Water_Quality` in `../ml model/Water Quality Classification for Rural Areas.csv`. It is returned alongside the latest reading by `GET /api/dashboard`. It does not certify potability or replace laboratory testing. The model uses only pH, TDS, turbidity, and temperature; it omits conductivity and dissolved oxygen because the current ESP32 does not send them. The training file contains only 10 `Good` examples, so that class is especially uncertain.

The deployable artifact `app/water_quality_model.joblib` is generated by `python train_model.py` from the repository dataset; `app/water_quality_model_metrics.json` contains its holdout metrics. Keep the training data, artifact, and pinned scikit-learn version together when deploying. Re-train after changing the dataset.
